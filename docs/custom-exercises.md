> **Важно**: сервер `100.workout.su` закрыт (2026-08-01), сетевой слой и пакеты `SWNetwork`/`SWKeychain` удалены. Приложение работает офлайн: все данные хранятся локально в SwiftData, синхронизации нет.

### Краткий обзор функционала

- **Список упражнений**: отображение пользовательских упражнений текущего пользователя, скрытие элементов, помеченных к удалению.
- **Пустое состояние**: CTA для создания первого упражнения.
- **Поиск и фильтр**: фильтрация по названию (локально, без сети).
- **Создание**: форма ввода названия и выбора иконки, локальное сохранение в SwiftData.
- **Редактирование**: предзаполнение полей, локальное сохранение изменений.
- **Удаление**: мягкое удаление (soft delete) — элемент помечается флагом `shouldDelete` и сразу скрывается из UI.
- **Навигация**: переходы список → добавление → редактирование.
- **Доступность и логирование**: логи на русском, UI не блокируется ожиданием сети.

### Модель данных: `CustomExercise`

- `id: String` — уникальный идентификатор (локально создается как timestamp + случайное число).
- `name: String` — название упражнения; локальная защита от дубликатов по имени для текущего пользователя.
- `imageId: Int` — идентификатор иконки.
- `createDate: Date` — дата создания.
- `modifyDate: Date` — дата последнего изменения (для аудита и сортировки).
- `isSynced: Bool` — deprecated; sync-флаг, оставлен только для стабильности схемы (сервер закрыт).
- `shouldDelete: Bool` — пометка на удаление (элемент скрывается из UI через `@Query`-предикат).
- `user: User?` — связь с пользователем (Relationship в SwiftData).

**Дополнительные методы модели:**

- `fetch(by:id:in:context)` — статический метод для получения упражнения по ID из контекста.
- `image: Image` — computed property для получения иконки упражнения.
- `exerciseSnapshot: ExerciseSnapshot` — преобразование в снимок (пережиток удаленного sync-слоя, активных потребителей нет).

### Офлайн-приоритет

- Все операции (создание, обновление, удаление) сохраняются локально в SwiftData.
- Сетевой слой удален (сервер `100.workout.su` закрыт) — синхронизации нет, все пользователи работают офлайн.
- Устаревшие sync-флаги (`isSynced` и связанные поля) сохраняются в модели только для стабильности схемы; новые sync-флаги не добавлять.

### Сервис: `CustomExercisesService`

Сервис помечен `@MainActor` и `@Observable`. Все логи — на русском языке (`OSLog`).

- **Создание**: `createCustomExercise(name:imageId:context:)`
  - Защищает от локального конфликта имен для текущего пользователя (добавляет суффикс со временем, если имя занято и элемент не помечен к удалению).
  - Создает локальный `id` на основе `timestamp` + случайного числа.
  - Вставляет в SwiftData и сохраняет; логирует успешное локальное создание.
  - Ошибка сохранения логируется, пользователь не блокируется.

- **Пометка как измененного**: `markCustomExerciseAsModified(_:context:)`
  - Проставляет `modifyDate = now` и `isSynced = false`, затем сохраняет контекст.
  - Может выбрасывать ошибку при сохранении контекста.

- **Удаление (soft)**: `deleteCustomExercise(_:context:)`
  - Не удаляет объект физически.
  - Ставит `shouldDelete = true`, `isSynced = false`, обновляет `modifyDate` и сохраняет контекст.
  - UI фильтрует такие элементы и не показывает их пользователю.

### Вспомогательные структуры

- **`ExerciseSnapshot`**: неизменяемый снимок данных упражнения (`id`, `name`, `imageId`, `createDate`, `modifyDate`, `isSynced`, `shouldDelete`, `userId`). Пережиток удаленного sync-слоя: используется только в `CustomExercise.exerciseSnapshot`, активных потребителей нет.

### Логирование

- **Все сообщения на русском языке**:
  - Создание упражнения (id, имя, результат разрешения конфликта имени).
  - Пометка как измененного и пометка к удалению.
  - Ошибки сохранения с `error.localizedDescription`.

### UI: взаимодействие и поведение

- Обычные операции создания/редактирования/удаления не блокируют UI; все изменения сохраняются в SwiftData сразу, без сети.
- Элементы с `shouldDelete == true` скрываются из списка через `@Query` с предикатом.
- Поиск реализован локально через фильтрацию по названию (без сети).
- Удаление через swipe actions с подтверждением через `confirmationDialog`.
- Навигация: список → детальный просмотр → редактирование (через `NavigationLink` и `sheet`).

### Тестирование и качество

- Юнит-тесты модели (`CustomExerciseTests`): снимки с пользователем и без, флаги `isSynced`/`shouldDelete`, создание новых экземпляров снимков — средствами Swift Testing.

### Принципы расширения

- Новые поля в `CustomExercise` добавлять с учетом мягких миграций SwiftData.
- Для новых операций соблюдать офлайн-приоритет: локальные изменения в первую очередь, без сетевых вызовов.
- Не добавлять новые sync-флаги (`isSynced`, `shouldDelete`, `lastModified`) — они deprecated и не используются.

### Ключевые правила

- Не блокировать UI ожиданием сети в экране упражнений.
- Всегда писать логи на русском с достаточным контекстом.
- Soft delete: сначала пометка `shouldDelete = true` и скрытие в UI; объект не удаляется физически.
