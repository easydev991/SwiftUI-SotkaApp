# Офлайн-приоритет (критически важно!)

## Когда применять

- При разработке любой функции, работающей с данными
- При создании новых моделей SwiftData
- При создании UI для отображения данных

## Контекст

- **Сети нет и не будет**: сетевого слоя в проекте нет.
- Приложение постоянно в read-only режиме (`AppConfiguration.isReadOnlyMode = true`), все пользователи offline-only.
- Легаси-флаги `isSynced`, `shouldDelete`, `lastModified` остались на моделях, но помечены `@available(*, deprecated)`. **Не добавляй новые такие флаги, не используй и не расширяй существующие.** Встретил на легаси-модели — оставь как есть, не строй на них логику.

## Основные принципы

### 1. Офлайн-first обязателен

- **Все данные хранятся локально** в SwiftData — это единственное хранилище
- **Сетевого слоя нет**: никаких запросов, очередей отправки, статусов синхронизации
- **UI работает только с локальными данными** из SwiftData

### 2. Паттерны локального хранения

- **Сохраняй** в SwiftData сразу при мутации (insert/update + сохранение контекста)
- **Читай** только из SwiftData — источник истины один, локальный
- **Не добавляй** флаги состояния сети/синхронизации на модели

### 3. Исключение — офлайн-логин

- Единственный «auth» — офлайн-логин (`AuthHelper`, UserDefaults-backed `isAuthorized`, sentinel-пользователь). Это **не сетевая фича** и **не прецедент** для новых сетевых или auth-фич — не добавляй их без явного запроса.
- **Логин** → данные пользователя сохраняются локально.
- **Логаут** → полная очистка всех данных пользователя (single-user: один активный пользователь за раз).

### 4. Правила для агента

При создании новых функций:

1. **Реализуй** локальное сохранение в SwiftData первым
2. **Не добавляй** sync-флаги и сетевые зависимости
3. **Тестируй** работу без интернета (он и так всегда «отсутствует»)

При работе с легаси-кодом:

1. **Встретил** `isSynced`/`shouldDelete`/`lastModified` — они deprecated, не расширяй использование
2. **Не чини** «синхронизацию» — её нет; если код на неё опирается, упирай в локальные данные

### 5. Тестирование

- **Тестируй** офлайн-функциональность каждой фичи (обязательное правило проекта)
- **Проверяй** сохранение и чтение локально (in-memory `ModelContainer` для детерминизма)
- **Проверяй** очистку данных при логауте

## Заключение

SotkaApp — офлайн-приложение без сети: SwiftData — единственное хранилище, офлайн-логин — единственный auth, один активный пользователь.
